**CodeWitness 0.1.11** stops losing a verification run to a five-second timeout. Two runs against the same
project is a normal thing to do, and SQLite allows one writer.

## What changed

- **A contended write is retried instead of abandoned.** SQLite's `busy_timeout` was a fixed five seconds with
  no retry; a second run that lost the race waited exactly that long and then gave up, which lost the whole
  run — nothing recorded, and the caller told about it in a warning while the exit code was computed from the
  verdicts alone. A save now waits 15 s for the lock and then retries with a doubling backoff (three attempts,
  roughly a second and a half in total) before failing.
- **Only contention is retried.** A read-only directory, an unopenable file and a corrupt database all fail
  identically however long you wait, so they are classified as restrictions and reported immediately. Retrying
  them would turn a clear failure into a slow one.
- **The failure names the cause.** If the contention outlasts the retries, the message says so, and the
  existing guarantee applies: a run whose evidence cannot be stored is a command failure (exit `3`), not a
  warning.
- The busy timeout and the retry budget are deliberately bounded. A run that cannot record its evidence should
  find out promptly rather than appear to hang.

## Verified for this release

- Full reactor test suite: **1721 tests, 0 failures** across all 22 modules (up from 1719).
- New tests pin the contract rather than a timing race: a write that loses the race either succeeds — in which
  case the run is readable back from a freshly opened store — or fails with a message that names the
  contention; and contention (`SQLITE_BUSY`, `SQLITE_LOCKED`) is classified separately from a restriction
  (`SQLITE_READONLY`) and from a defect (`file is not a database`), because only the first is worth retrying.

## Compatibility

- No report format, verdict, exit code, CLI or configuration change. A single uncontended run behaves exactly
  as before; it no longer waits five seconds before failing when something else is writing.
