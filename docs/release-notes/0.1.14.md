**CodeWitness 0.1.14** removes the last fourteen copies of the security-analysis ceremony. Every adapter's
security provider is now a constructor call, because none of them contained a rule.

## What changed

- **One forwarding implementation.** `DelegatingSecurityAnalyzer` in `codewitness-adapter-support` does what all
  fourteen did: report an id, claim one language, and hand the analysis to the heuristic analyzer that owns the
  rules. Each adapter keeps a named class — `SwiftSecurityAnalyzer`, `RustSecurityAnalyzer`, … — because the
  bundle that registers it, the test that asserts its id and a stack trace all name a language, and reading a
  named class at the registration site is clearer than reading a lambda. What is gone is fourteen copies of the
  same three methods.
- **The behaviour stays where it belongs.** A security rule lives in the language's heuristic table, which is
  what makes a rule defined once instead of twice; the forwarding never contained a rule, a threshold or a
  language quirk. The two adapters that really do filter (Java takes the security entries out of its heuristic
  scan, Kotlin calls a security-specific method) keep that filter, expressed as the delegate.
- **A `null` from an analysis becomes an empty list.** The engine's contract is that it never sees a null where
  it expects findings, and a new provider should not be able to break that by forgetting a `return`.
- The SQL adapter is untouched: its security analysis reads a schema rather than a rule table, and is a real
  implementation.

## Verified for this release

- Full reactor test suite: **1728 tests, 0 failures** across all 22 modules (up from 1725).
- **276 net lines removed** across 15 files, with every adapter's own security test passing unchanged — the
  evidence that the consolidation preserved what each provider returns, its id and the language it claims.
- New tests pin the shared contract: the id it was given is the id it reports, it claims only its own language, a
  missing project is not one it supports, the findings it returns are exactly the analysis's, and a `null`
  analysis becomes an empty list.

## Compatibility

- No report format, verdict, exit code, CLI or configuration change. Provider ids are unchanged, so suppression
  entries and baselines that name them keep working.
