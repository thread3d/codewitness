**CodeWitness 0.1.18** is the third step of decomposing the verification engine: the security phase joins static
analysis as a method rather than an inline lambda.

## What changed

- **`securityPhase(scope, analysable)` replaces the inline lambda.** It had the same skeleton as static analysis —
  loop over the languages that built, build a per-language context, call the providers, deduplicate, record
  evidence, merge the outcome — and differed only in which providers it asks and which evidence type it writes.
  With both extracted, that shared shape is visible in two methods instead of something a reader reconstructs by
  comparing seven lambdas.
- `verify()` is down from 670 lines to **638**, and two of its seven phases now live outside it.
- The remaining five phases are untouched: the build, tests, coverage, mutation and dependencies bodies each
  extract as their own verifiable change, and the suite is the same 1729 tests as before this one.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules, unchanged from before the change.
- The phase is exercised by the engine tests that assert what the security scan records and by every adapter's
  security test, which drives its rule table through this path; nothing about its observable behaviour moved.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference.
