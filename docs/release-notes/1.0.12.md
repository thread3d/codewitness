**CodeWitness 1.0.12** is a documentation correction. It removes a claim the tool has made false, and writes down where
the newest feature stops.

## What changed

- **The landing page no longer says the tool cannot verify its own exit codes.** Since 1.0.2 that sentence has been
  wrong: the self-check verifies all seven of its ground rules by execution, including the exit-code contract, which
  is checked by running the built jar and observing what it returns. A project whose argument is "we only assert what
  we observed" cannot leave a stale paragraph asserting something it no longer believes — and this one had survived
  four releases because it lived in prose nobody re-read.
- **The status document now describes the four scenario modes** and, specifically, what `process` does that the other
  three cannot: a generated test calls code *inside* the project's framework, while a process scenario observes what a
  caller of the built program sees. It also states the bound of the new feature plainly — `native_test` generates a
  JUnit or `unittest` case on **Java and Python only**; on the other fourteen languages the engine stands aside and the
  generator has nothing to write, so the scenario is not executed and the run says so.
- **That sharp edge is pinned by a test** rather than left as prose. A `native_test` scenario handed to the engine
  produces no evidence, a note explaining why, and an `UNVERIFIED` outcome — so "it is reported, not silently passed"
  is now a property the suite checks.
- **The 1.0.11 release notes gained the caveat their own reference document already carried**, and this release exists
  partly because the two disagreed.

## Verified for this release

- Full reactor test suite: **1751 tests, 0 failures** across all 22 modules (up from 1750).
- The corrected claims were each checked against the code before being written: the self-check's seven `VERIFIED`
  verdicts and the mutation score from the run recorded in `docs/status.md`, and the `native_test` behaviour from the
  new strategy test.

## Compatibility

- Documentation only. No code, report format, verdict, exit code, CLI or configuration change — the one code change is
  a test.
