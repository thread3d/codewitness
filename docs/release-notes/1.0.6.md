**CodeWitness 1.0.6** finishes the adapter conversion: fourteen of sixteen adapters now declare their tools once, and
the two that cannot say why.

## What changed

- **SQL and C++** extend `AbstractLanguageAdapter` and declare their provider set once. Both were pure delegations
  all along; they had simply been left out of the earlier batches.
- **Java and Kotlin are deliberately not converted, with the reason now pinned by a test.** Their `build`,
  `runTests` and `analyze` are not delegations: they select a build system for the project first — Maven or Gradle,
  from the detected project attributes — and construct the provider around it. Forcing them through the base class
  would mean either hiding that selection behind a provider that resolves per project, or dropping it. Neither is an
  improvement dressed up as consistency.
- **`AdapterCapabilityTest` now asserts the boundary**: the adapters that do not extend the base class are exactly
  `java` and `kotlin`. An adapter that skips the base class without a reason is a visible change rather than
  something assumed at review time.
- SQL's conversion is worth noting for what it revealed: it registers a `SqlTestGenerator` and a
  `SqlGeneratedTestExecutor` rather than the `*ScenarioTestGenerator`/`*GeneratedTestRunner` names the other adapters
  use, which is why a name-based transform needed care — the roles are the same even when the nouns are not.

## Verified for this release

- Full reactor test suite: **1743 tests, 0 failures** across all 22 modules (up from 1742).
- SQL's and C++'s own tests pass unchanged: schema loading and constraint probing for SQL, CMake configure and CTest
  for C++, mutation and scenario generation for both.
- The capability contract from 1.0.5 still holds: the adapters with no dependency inventory remain exactly Pascal,
  SQL, Verilog and VHDL, and the HDL three still claim no coverage.

## Compatibility

- Internal: no report format, verdict, exit code, CLI or configuration change. Provider ids are unchanged.
