**CodeWitness 0.1.19** is the fourth step of decomposing the verification engine, and the largest so far: the
dependency phase comes out of `verify()`, which is now under 600 lines.

## What changed

- **`dependenciesPhase(scope, inspections, builds)` replaces the inline lambda.** It was the worst of the seven:
  a loop with a three-way conditional for the analyzer, inside it an advisory scan gated on configuration, inside
  that an evidence builder with nested ternaries — and the only phase whose empty result has two different
  meanings. Extracting it put the ambiguity it guards against next to the guard, rather than at the bottom of a
  method that had already done six other things.
- `verify()` is down from **670 lines to 578**, with **three of its seven phases** now methods: static analysis,
  security and dependencies.
- The remaining four — build, tests, coverage and mutation — each extract as their own verifiable change. The
  suite is the same 1729 tests as before this one.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules, unchanged from before the change.
- The phase is exercised by the engine tests that assert what the dependency scan records, including the case the
  extraction was chosen for: an empty selection that must name a failed build rather than claim no analyzer is
  registered.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference.
