**CodeWitness 1.0.7** rewrites the boundary-case enumeration so every input moves, and fixes a non-determinism that
continuous integration found in `clean --keep`.

## What changed

- **Boundary sampling exercises every input.** The enumeration took the head of a breadth-first product, which pins
  the earliest-declared inputs at their first value: with four inputs of six values each, the twelve kept cases
  varied the third and fourth and never moved the first two. Nothing in the report said so — the scenario simply
  ran fewer experiments than its author asked for.
  Cases are now built in three passes: a **baseline** with every input at its first declared value; then variation
  **round-robin across the inputs**, so each input gets its next value before any input gets a third; then **pairs**
  with whatever budget is spare, because two inputs varying together is where an interaction shows up. The guarantee
  is asserted for one to eight inputs: every input varies, every case names every input, and the count never exceeds
  the cap.
- **`clean --keep` is now a total order.** CI failed the end-to-end job on this, and it was right to: `--keep`
  ordered run directories by modification time alone, and times tie whenever two runs are created inside the same
  clock tick — which a fast filesystem allows and a script can cause. The surviving run then depended on the order
  the directory stream happened to return, so CI kept the older run while a developer machine, whose clock is
  slower, kept the newer. The name is now the tie-break, and a test sets two identical modification times to pin it.
- **A process lesson, recorded rather than glossed.** The previous four releases were pushed faster than CI runs, and
  the `ci.yml` concurrency group cancelled each in-flight run when the next push arrived. The end-to-end fixture
  suite — the only thing that exercises real toolchains — therefore ran for the first time in five releases on this
  one, and it found the `clean` defect immediately. A release cadence faster than the verification cadence means the
  verification stops happening.

## Verified for this release

- Full reactor test suite: **1746 tests, 0 failures** across all 22 modules (up from 1743).
- New tests pin the enumeration's guarantee (every input varies, for one to eight inputs; the first case is the
  baseline; one input's variation leaves the others at their first value; pairs come last) and the tie-break.
- **The end-to-end job passed on this commit**, which is the gate that matters for this release: it builds every
  fixture with its own real toolchain — Maven, Cargo, `go`, Node, .NET, CMake, Composer, Bundler, Swift, Icarus
  Verilog, Free Pascal and GHDL — and the new boundary sampling changes which generated cases those fixtures run. The
  same job that found the `clean` defect now reports every step green, so the sampling change did not break a
  single fixture.

## Compatibility

- Which generated cases run changes for any scenario whose product exceeds the cap — that is the point of the
  release. A scenario under the cap generates the same cases as before. No report format, verdict, exit code or
  configuration change.
