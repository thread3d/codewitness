**CodeWitness 1.0.14** closes the last backlog item: the per-phase progress line now accounts for suppression, so the
two numbers a reader meets first no longer contradict each other.

## What changed

- **The phase line says how much of what it counted will not reach the report.** Running the tool on itself printed
  `[static-analysis ] 2 medium` and `[security ] 3 high`, and the report then contained none of them, because
  suppression is applied once after every phase — a finding is advisory, so filtering at collection would have to be
  repeated in each phase. Both statements were true and the reader was left to work out why they differed. They now
  read `2 medium (2 suppressed by configuration)` and `3 high (3 suppressed by configuration)`.
- **The phase cannot ask the report, so it asks the configuration**, with the same predicate the suppression pass
  uses. One helper decides both, so the count and the filter cannot drift: a suppression entry that covers a finding
  is exactly what makes it missing from the report and exactly what the phase counts.
- **A process note worth more than the fix.** My first attempt at the change replaced the two call sites with a
  string substitution that silently matched nothing — the code still called the old one-argument helper, the new unit
  test passed because it tested the helper directly, and only running the tool and reading its own output showed the
  annotation was missing. That is the failure mode recorded in this project's own history (1.0.13 rebuilt a backlog
  table whose rows had been lost the same way), and it is why the final change asserts the number of sites it edits.

## Verified for this release

- Full reactor test suite: **1755 tests, 0 failures** across all 22 modules (up from 1754).
- The helper is tested from three sides: a suppression matching the finding adds the note, no suppressions leaves the
  count alone, and a suppression for a different rule does not change this phase's sum.
- The end-to-end check is the run itself: the self-check now prints
  `[static-analysis ] 2 medium (2 suppressed by configuration)` and `[security ] 3 high (3 suppressed by configuration)`,
  still reports all seven ground rules `VERIFIED`, and still ends with no unexplained findings.

## Compatibility

- One line of progress output changes; nothing else. No report format, verdict, exit code, CLI or configuration change.
