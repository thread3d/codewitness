**CodeWitness 0.1.17** is the second step of decomposing the verification engine: the largest of the seven inline
phase lambdas is now a method.

## What changed

- **`staticAnalysisPhase(scope, analysable)` replaces the inline lambda.** It was the largest of seven phase
  bodies buried inside the 663-line `verify()` — around fifty-five lines of loop, provider dispatch, evidence
  construction and outcome merging — and reading any one of them meant reading all seven, because they share a
  skeleton and differ only in which providers they call and what they record.
- The phase takes the run scope and the languages to analyse, and nothing else. That is the point of last
  release's `RunScope`: a phase can now be called, read and tested without a reference to a method that also
  builds the report and computes every verdict.
- The scope gained the provider registry, because a phase that no longer lives inside `verify()` cannot reach the
  field that method has. That is a deliberate widening: the registry is a run-wide fact like the rest of the
  scope, not a special case.
- The remaining six phases are untouched. Each extraction is a separate, verifiable change, and a refactor that
  alters behaviour is a refactor that failed — so the suite is the same 1729 tests as before.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules, unchanged from before the change.
- The extracted phase is exercised by the engine tests that assert what static analysis records (evidence,
  findings artefact, `staticAnalysisRan`) and by the adapter suites that drive their own analyzers through it;
  nothing about the phase's observable behaviour moved with it.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference.
