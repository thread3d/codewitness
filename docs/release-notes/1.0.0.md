**CodeWitness 1.0.0** is a promise about what will not break, made with the same condition the tool applies to
everyone else's code: say exactly what you examined, and say what you did not.

## What changed

- **The version.** Every module, the parent pom and the version the tool reports are `1.0.0`. Nothing else in the
  product changed: 1.0 is a statement about the contract, not a rewrite.
- **The contract is now written down** in `README.md` under *Versioning and what 1.0 means*. It covers four things
  and only four: the command line (commands, flags, exit codes), the report documents (`report.json` keys, the
  SARIF profile, the verdict vocabulary), every `codewitness.yaml` key, and the adapter SPI. Adding to any of them
  is a minor release; renaming or removing is a major one. Internal structure, the artefact layout under
  `.codewitness/runs/` and the wording of a limitation are explicitly *not* part of it — calling implementation
  details an interface would freeze mistakes.

## What 1.0 is not

A version number is easy to read as a claim, so this release states the claim precisely.

- **It is not a claim that verification is complete.** The project's own self-check reports one requirement
  `UNVERIFIED` — `CWR-007`, the exit-code contract — because a scenario can only be `single`, `sequence` or
  `concurrent`, so nothing about a *process* can be asserted. That is the honest answer, and it is in the backlog.
- **It is not a claim that every language is verified to the same depth.** Seventeen adapters exist; they differ in
  which phases they can run, and each report names what it could and could not do for the languages it found. An
  HDL design has no dependency inventory and no coverage; a project with no test runner says so instead of passing.
- **It is not a claim that findings are correct.** Heuristic rules are advisory, a match is a hint, and no
  requirement is failed on a rule's word alone.
- **It is not a security boundary.** The `local-process` sandbox replaces the environment and bounds the work; it
  does not contain a hostile build, and every report says so.
- **It is not an empty backlog.** `docs/backlog.md` lists the open work with its reasoning.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules.
- The three version numbers agree: the root pom, the constant the tool reports, and — for the first time — the tag,
  which is what the release workflow checks before it will publish anything.
- The jar attached to this release reports `1.0.0` when run, which is the only check that does not need a project
  to verify.

## Compatibility

The previous release was 0.1.21. Because 1.0.0 is the first release to declare the contract, everything a user
observes today is unchanged: same commands, same flags, same exit codes, same report keys, same configuration,
same SPI. A consumer that worked against 0.1.21 works against 1.0.0 without modification.
