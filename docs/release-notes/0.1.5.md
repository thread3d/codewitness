**CodeWitness 0.1.5** is a correctness release. It closes the places where the report or the exit code
could assert something the run had not established — the one class of bug that matters in a tool whose
whole product is evidence — and fixes a data-leak hazard in the isolated workspace copy.

CodeWitness does not generate code. It compiles the project, runs its tests, analyses it,
generates additional adversarial tests, executes them, looks for counterexamples, and reports
what it actually observed — with the evidence attached. A language model's opinion is recorded
as a suggestion and never counted as proof.

## What changed

### The report no longer renders a blocked run as a pass

- **`BuildSummary` was rendered by neither writer.** The engine filled it, the index persisted it, and
  the human report dropped it, so a failed build — the reason a run is `BLOCKED` — was invisible outside
  the evidence appendix. `report.html` now has a **Build** section (attempted, result, command, error and
  warning counts, duration, note) and `report.json` has a top-level `build` object.
- **`RunStatus` never reached the HTML.** The header showed `overallStatus()`, which aggregates verdicts,
  so the polyglot case the engine documents — one language fails to build, another language's requirements
  are fully evaluated, run status `BLOCKED` — rendered as a green page. The header now states the run
  status beside the verdict status, and a run that did not complete prints a banner saying so.
  `report.json` gains a top-level `runStatus` beside `status`.
- **Two verdicts for one requirement id collapsed by last-write-wins**, so the requirement card could say
  `VERIFIED` while the headline counted a `FAILED` one — a document that contradicted itself about the
  least favourable fact it knew. Both writers now keep the **most severe** verdict and state the
  collision. The shared rule lives in `StatusSeverity`.
- The header no longer prints the status twice (`✗ FAILED FAILED (…)`).

### A test harness failure is no longer reported as "no evidence"

- **pytest's plugin auto-loading is disabled for generated-test runs.** The generated tests are plain
  `unittest` cases and need no plugin, but pytest loads every plugin in the interpreter, and a
  third-party plugin that fails at import time aborts collection before a single case runs. Reproduced
  against a real interpreter: a scenario whose generated test *did* find a counterexample was reported
  `UNVERIFIED` with exit `0`. It now reports `FAILED` with exit `1`. The project's own suite is left
  alone, because a project may legitimately depend on its plugins; `reproduce` emits the same isolated
  command, so a replay reproduces what the run saw.
- **The stdlib runner is a fallback** when pytest still produces no report, because the generated test
  needs nothing but the standard library, and "the runner would not start" is not "no counterexample".

### Declarations that cannot take effect are stated

- **A scenario naming an id the requirements document does not declare** was never visited — the planner
  matches scenarios by walking the requirements — so a typo silently disabled the only executable
  evidence for a requirement, and the run reported `UNVERIFIED` as though no scenario existed. It is now
  named on the console and in the limitations.
- **A requirements document with a repeated heading** now says so, for the same reason: every verdict,
  table and index keyed by that id has to guess which occurrence is meant.

### The workspace copy no longer leaks host files

- **Symbolic links are neither followed nor copied.** `Files.copy` materialised a file link's target
  into the run workspace, which is kept on disk and travels with a bug report: a repository containing
  `.env -> ~/.aws/credentials` caused CodeWitness to copy the user's credentials into
  `.codewitness/runs/<id>/workspace/`. A directory link was turned into an empty directory, silently
  changing the tree. Every skipped link is listed in the run's limitations, so a project that needs one
  fails visibly instead of being verified against a different tree.

### Storage tells the truth about itself

- **The schema has a version** (`PRAGMA user_version`, currently 2) with an ordered migration path. Every
  statement was `CREATE TABLE IF NOT EXISTS`, which is a no-op against an older column set, so the first
  column added after this release would have made every insert fail against an existing history. A file
  written by a newer build is now refused rather than written to.
- **Version 2 keys `requirements` by `(run_id, ordinal)`** rather than `(run_id, requirement_id)`, which
  made a run with a repeated requirement heading impossible to store: the second insert violated the
  primary key, so a run that verified two requirements recorded neither. Existing files are upgraded in
  place.
- **`clean` keeps the newest runs and deletes the index rows too.** It sorted run directories by *name*,
  but a run id is a date plus five random characters, so within one day `--keep 3` deleted the newest run
  and kept the oldest. It also deleted only the directories, leaving rows that `report` then listed as
  runs whose reports did not exist.
- **A run whose result cannot be stored is a command failure (exit `3`), not a warning.** It used to print
  one yellow line and exit on the verdicts alone, so a full disk or an unreadable index lost the run while
  the exit code said success.
- Opening a database reports the reason it failed, not just the path.
- **`report` says when a run's files are gone.** A run kept only in the index printed the paths of a
  directory that had been deleted as though the full report could be opened there. It now says the entry
  came from the index and that the files no longer exist, and it only offers a path it can check.

### A truncated run says which limit stopped it

- **Reaching `max_generated_tests` or `max_llm_calls` marks the run truncated.** Only `max_duration` was
  ever recorded, so a run stopped by a cap reported `exhausted: false` with no reason — indistinguishable
  from a run that finished. `budget.exhaustedReason` now names the limit, and the run status derives from
  it as the README already promised.

### Smaller corrections

- **`BLOCKED` still outranks a counterexample** — a project that does not build cannot be verified as a
  whole, and that ordering is a documented ground rule exercised by the self-check. What no longer happens
  is the counterexample disappearing: the verdict's reason names it and it stays in the report.
- **The static-analysis findings artifact is written by Jackson.** It was hand-built JSON escaping only
  backslash, quote and newlines, so a tab or other control character in a compiler or analyzer message
  produced an unparseable file.
- The evidence artifact and the report agree on what a skipped phase and a truncated budget mean.

## Verified for this release

- Full reactor test suite: **1684 tests, 0 failures** across all 22 modules (up from 1671; the new tests
  cover the symlink guard, the build section and run status, the duplicate-verdict collapse, the budget
  limit reason, the schema version, the v1→v2 migration, `clean`'s ordering and index pruning, and `report`
  stating a missing run directory).
- End-to-end checks against the built jar, each one a defect reproduced before the fix and absent after:
  - a `.env` symlink to a file outside the project is no longer copied into the run workspace, and the
    skip is listed in the limitations;
  - a scenario whose generated test finds a counterexample now reports `FAILED` and exits `1` under an
    interpreter whose third-party pytest plugin breaks collection (was `UNVERIFIED`, exit `0`);
  - a scenario naming an undeclared requirement id, and a repeated requirement heading, are both named on
    the console and in the report, and the run is stored (was: silently dropped, and unstorable);
  - a run truncated by `max_generated_tests` reports `exhausted: true` with a reason and run status
    `BLOCKED` (was: `exhausted: false`, `COMPLETED`);
  - a blocked run's HTML carries the banner, the run status row and the failed build section;
  - `clean --keep 1` keeps the newest run by time when name order disagrees with it, and removes the
    index rows of the runs it deleted, so `report` lists exactly what survives.

## Compatibility

- `report.json` gains `runStatus` and `build` at the top level, and `build` inside the object written to
  the index. Existing consumers keep working: no key was removed or retyped.
- Exit code `3` now also covers "the run completed but its result could not be stored". A CI job that
  treated a stderr warning as success will now see the failure.
- The run index is upgraded on first open (`user_version` 1 → 2), including files written before the
  version existed (`user_version` 0). Verified against this repository's own history, which was created
  by 0.1.4 and migrated in place. Downgrading is not supported: 0.1.4 refuses to open a file written by
  0.1.5, which is the point of the version.
- Symbolic links inside a verified project are not copied. A project that builds through a link into its
  own tree will now fail to build in the copy, with the skipped link named in the limitations.
