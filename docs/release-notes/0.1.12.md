**CodeWitness 0.1.12** bounds what a project can do to the report about it. The report is written from data the
project controls and it is the artifact a user keeps, emails and shares.

## What changed

- **One unencodable string no longer destroys the run.** A hostile test report can contain an unpaired surrogate
  (`"\ud800"` in a JSON report decodes to one), which travels through the adapters untouched and reaches the
  writer, where `Files.writeString` throws `UnmappableCharacterException` before writing anything. Because the
  caller writes both report files and the SQLite record in one block, that also lost the durable record: every
  verdict the run established became unavailable because one string was not encodable. All three writers now
  replace an unpaired surrogate with U+FFFD — Unicode's own "there was data here that could not be represented"
  — so the rest of the report survives and the damage is visible. A paired surrogate, an ordinary character
  outside the basic plane such as an emoji in a test name, is left alone.
- **The HTML report declares a Content-Security-Policy.** Nothing in it is executable today: no script, no event
  handler, no external reference. But a report is written to be emailed, archived and opened from `file://`, so
  `default-src 'none'` with only the inline stylesheet allowed means that an interpolation that ever slips past
  the escaping cannot reach an attacker's host.
- **Tables are bounded at 500 rows, and the truncation is stated.** A project decides how many warnings its
  compiler emits; two million findings is a report nobody can open, and the writer builds the whole document in
  memory. The findings and failing-test tables now stop at 500 rows with a line saying how many were not shown.
  Nothing is discarded — the full set stays in the JSON report and in the evidence appendix — so the bound is a
  rendering limit, not a data limit, and it says which it is.
- Control characters are deliberately *not* rewritten. They are a rendering oddity, not an encoding failure, and
  a report that silently alters a byte the tool actually observed would be the worse fault.

## Verified for this release

- Full reactor test suite: **1725 tests, 0 failures** across all 22 modules (up from 1721).
- New tests pin each guarantee: the CSP is present and allows only the report's own stylesheet; a finding
  containing an unpaired surrogate still produces both files, and the replacement character is visible in each;
  a valid surrogate pair survives untouched; and a 900-finding report renders 500 rows with the count of the
  rest stated.

## Compatibility

- The HTML report gains one `<meta>` element and may truncate a long table with a paragraph saying so.
- An unpaired surrogate now appears as U+FFFD instead of aborting the run. No other content changes.
