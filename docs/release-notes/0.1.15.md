**CodeWitness 0.1.15** closes a way a verification could be quietly narrower than it reported. An adapter
declares which phases it supports and registers the providers that implement them, and nothing connected the
two.

## What changed

- **The engine now checks declared capabilities against registered providers at the start of every run.** An
  adapter that registers a coverage provider but forgets `Capability.COVERAGE` had its coverage phase skipped
  silently — the run looked complete, and simply had no coverage section, while the provider sat in the registry
  unused. That is now a stated limitation and a self-issue naming the adapter and the capability.
- **Only one direction is checked, deliberately.** "Declares a capability but registers no provider" is not a
  defect: an adapter may implement a phase itself, which is what `LanguageAdapter.build` and its siblings are
  for — a test adapter that throws from `build` is doing exactly that. Treating that as a fault made the check
  fire on legitimate adapters, which the existing `SelfIssueRecordingTest` caught before this shipped. The check
  therefore reports only the case that can have no innocent explanation: a provider exists, and the phase it
  implements will not run.
- No adapter in the tree is affected — every one declares what it registers — so this is a guard against the next
  one, and the release says so rather than implying a fix to existing behaviour.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules (up from 1728).
- A new engine test constructs an adapter that declares `INSPECT` and `BUILD` while an orphan coverage provider
  is registered for it, and asserts both that the run's limitations name the skipped phase and that the message
  names the capability. Without a deliberately-wrong adapter the guard would be untested code, which is how the
  risk it addresses arises in the first place.

## Compatibility

- New limitation text on runs whose adapters have a provider/capability mismatch. No report format, verdict,
  exit code, CLI or configuration change; no run in the tree gains a limitation.
