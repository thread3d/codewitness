**CodeWitness 0.1.20** finishes this stretch of engine decomposition with the build phase, and puts the project's
backlog in the repository.

## What changed

- **`buildPhase(scope, builders, builds)` replaces the inline lambda.** It is the one phase whose body writes into
  the state later phases read — the per-language build results and the merged build — so extracting it meant
  passing those in rather than capturing them. Making that ownership explicit is why it was worth doing alone: a
  phase that mutates state another phase depends on is exactly what a reader needs to see at a glance.
- `verify()` is down from **670 lines to 545**, with **four of its seven phases** now methods: build, static
  analysis, security and dependencies. Tests, coverage and mutation remain inline and follow the same shape.
- **`docs/backlog.md`** records what is known to be wrong or worth doing, with the reasoning, and a table of the
  release that closed each finished item. A backlog that lives in a conversation expires with the conversation;
  this one travels with the code, which is the same argument that put the release notes here in 0.1.13.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules, unchanged from before the change.
- The build phase is the most heavily exercised path in the suite — every engine test drives it, the polyglot
  tests assert its per-language results, and the end-to-end fixture tests compile real projects through it.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference.
