**CodeWitness 1.0.4** converts the eight remaining uniform adapters to the derived-capability pattern: nine of sixteen
now declare their tools once, and their capabilities are computed from that declaration.

## What changed

- **Python, Go, TypeScript, JavaScript, C#, PHP, Ruby and Swift** now extend `AbstractLanguageAdapter` and declare
  their provider set once in a static `PROVIDERS` field. Their `build`/`runTests`/`analyze` delegations and their
  hand-written `capabilities()` lists are gone; `AdapterBundle.register` registers the same declaration the adapter
  is built from.
- **The conversion was checked for what it deleted, not only for what it compiled.** The transform removes
  everything after `build()` in each adapter, so the diff of each converted file was examined line by line: in all
  eight, the only removed code is the class declaration's `implements LanguageAdapter` clause and the hand-maintained
  capability list. Nothing else was lost — which is the only thing that makes a mechanical refactor of nine files
  safe to claim.
- **Seven adapters are deliberately left alone for now**, and they are exactly the ones a transform cannot do
  correctly: Java (build-system selection), Kotlin (Maven and Gradle build systems rather than one build provider),
  C++ (CMake configure and build), SQL (schema and migration loading instead of a build), and Verilog, VHDL and
  Pascal (no coverage provider and no dependency inventory). For those three, the derived capability set will be
  *smaller* than today's hand-written one — correctly so, since a capability nobody can serve is a phase that runs
  and finds nothing — and each needs its behaviour inspected rather than pattern-matched.

## Verified for this release

- Full reactor test suite: **1739 tests, 0 failures** across all 22 modules.
- Each converted adapter's own tests pass unchanged: detection, build, tests, coverage, mutation, dependencies and
  scenario generation all still exercise the same providers, now reached through one declaration.
- The 0.1.15 capability guard, which reports an adapter that registers a provider for a phase it does not declare,
  has nothing to report: with the capabilities derived there is no second list to disagree.

## Compatibility

- Internal: no report format, verdict, exit code, CLI or configuration change. Provider ids are unchanged, so
  suppression entries and baselines that name them keep working.
