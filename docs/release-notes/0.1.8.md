**CodeWitness 0.1.8** removes the last five private copies of the helper that quotes a failing tool's output,
and with them a divergence that made a report say different things depending on the language it was about.

## What changed

- **One implementation of "the tail of a tool's output".** `Text.lastLines` in `codewitness-adapter-support`
  is now the only one. Eleven adapters already delegated to it; the five that had their own copy — the Java
  test provider and Maven dependency analyzer, and the Kotlin test provider, dependency analyzer and mutation
  tester — now delegate too.
- **A silent behavioural divergence is gone.** Three of those five copies stripped each line before quoting
  it, so the same compiler output appeared with different whitespace in a Kotlin report than in a Java one. A
  caret-indented diagnostic quoted back to a reader no longer lines up with the line it is about; that is
  invisible until it matters, which is the worst kind of drift.
- The shared behaviour is now pinned by tests: nothing to show says `(no output)` rather than nothing, only
  the last *N* lines are kept, a kept line keeps the indentation the tool gave it, and a Windows toolchain's
  carriage returns are handled.

This is a maintainability release: no report format, verdict, exit code or CLI change.

## Verified for this release

- Full reactor test suite: **1707 tests, 0 failures** across all 22 modules (up from 1703).
- The Kotlin adapter's diagnostic paths are covered by the same assertions as Java's, in `TextTest`.
