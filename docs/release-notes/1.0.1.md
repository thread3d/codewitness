**CodeWitness 1.0.1** brings the release workflow into the repository. It is the first release whose jar was built,
checked and published by the project rather than by hand.

## What changed

- **`.github/workflows/release.yml` is in the repository**, running on a `v*` tag. It refuses to publish unless the
  tag, the root `pom.xml` version and the version the tool reports all agree; builds the shaded jar with Temurin 25
  (the release target the project declares); checks that the jar exists, runs, and reports the version being
  released; and attaches it to a GitHub release whose notes come from `docs/release-notes/<version>.md`, falling
  back to a generated changelog so a tag never fails for want of prose.
- **No third-party action was added.** `gh` is on the runner and the token is the workflow's own, so the supply
  chain stays at the two actions CI already pins to commit SHAs — which this workflow pins to the same SHAs.
- Tests are deliberately **not** re-run in the release job: CI runs the full reactor suite on every push to `main`,
  and a release is a tag on a commit that already passed it.
- The workflow existed as a file for two releases before this one, unable to land because the token this work was
  done under lacked the `workflow` scope that GitHub requires for `.github/workflows/`. That is worth recording:
  the blocker was a credential, not a design, and no amount of retrying would have resolved it.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules.
- **This release is its own test.** The tag `v1.0.1` was pushed and the GitHub Actions run published the release —
  the jar attached to it was built by the workflow, having passed the three-way version check and the
  `java -jar … version` smoke check that the workflow performs. No release was created by hand for 1.0.1.
- `gh workflow list` reports the workflow as `Release — active`, so GitHub has accepted its syntax as well as its
  intent.

## Compatibility

- No change to the tool: no report format, verdict, exit code, CLI or configuration behaviour differs from 1.0.0.
