**CodeWitness 0.1.16** is the first step of decomposing the verification engine: the per-language context
plumbing that every phase copied out by hand is now one run-scoped object.

## What changed

- **One `RunScope` instead of sixteen arguments, eight times.** Every phase built a `VerificationContext` per
  language by calling `contextFor(...)` with sixteen arguments, seven times over, with an identical tail. Only two
  of those arguments could actually differ — the inspection and the requirement-to-code map — so the signature
  claimed fifteen degrees of freedom where there were two, and any new run-wide fact had to be threaded through
  every call site in lockstep.
- The invariant fourteen now live in a private record built once per run, immediately after the last run-wide
  fact exists. Each call site is now `contextFor(scope, inspection, codeMap)`, and adding a run-wide fact is one
  field in one place.
- This is deliberately a **first step, not the decomposition**. The 670-line `verify()` still holds seven inline
  phase lambdas; extracting those needs a scope object to hand them, which is exactly what this change creates.
  Splitting a method that builds the whole report and computes every verdict in one body is not a change to
  attempt without room to verify it properly, and the phases that remain inline are unchanged here.

## Verified for this release

- Full reactor test suite: **1729 tests, 0 failures** across all 22 modules — the same 1729 as before the change,
  which is the point: a refactor that alters behaviour is a refactor that failed. Every engine test, every
  adapter test and the end-to-end fixture suite exercise the phase construction this touched.
- `contextFor` now takes three arguments at all eight call sites; the sixteen-argument signature and its seven
  duplicated argument lists are gone. `context(...)` became static, which is what makes the derivation a pure
  function of the scope and the inspection.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference. This release exists
  to make the next one smaller.
