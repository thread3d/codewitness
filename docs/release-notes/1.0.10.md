**CodeWitness 1.0.10** finishes the engine decomposition. `verify()` has gone from 670 lines to 360, and what is left
of it is the sequence of phases rather than any one phase.

## What changed

- **The per-requirement strategy loop is `runStrategies`.** It carries three things that were easy to lose inside a
  400-line method: strategies run against the language a requirement is *written in*, not the union of every language
  in the tree (handing a Python requirement Java's test runner produces a recipe for a command that cannot run); an
  obligation no strategy touched is recorded as unverified rather than left absent, because a renderer that must
  invent a default will invent a flattering one; and a strategy that throws is a fault in the strategy — a note and a
  self-issue — rather than a finding about the project, so the remaining strategies still run.
- **The verdict loop is `computeVerdicts`.** It is four lines of interest and one comment that matters: blocking is
  *per language*. A requirement written in a language that compiled is not blocked by a sibling language that did
  not.
- **The report assembly is deliberately left alone.** It is eleven lines of
  `builder().verdicts(...).evidence(...).build()`. Extracting it would need a method with twelve parameters — a
  signature longer than the body — and would move the reader further from the data. A refactor has to leave something
  easier to read, not merely smaller to count, and saying so is part of the change.

## Verified for this release

- Full reactor test suite: **1747 tests, 0 failures** across all 22 modules — the same count as before the change,
  which is the point: the two extractions were pure moves.
- The engine's own tests exercise both extracted methods heavily: strategy ordering and fail-fast, the unverified
  default for an untouched obligation, a strategy that throws, per-language blocking in the polyglot tests, and the
  self-check's seven ground rules end to end.
- `verify()` measured at **360 lines** after the change, against 433 before and 670 when the decomposition began.

## Compatibility

- No behaviour change: no report format, verdict, exit code, CLI or configuration difference.
