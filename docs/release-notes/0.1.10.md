**CodeWitness 0.1.10** consolidates the hardening that protects the parser from the project being verified.
Nine copies of it existed across seven adapters, and they were not identical.

## What changed

- **One hardened XML loader.** `XmlDocuments` in `codewitness-adapter-support` is now the only way a test
  report, coverage report or build file is parsed. The nine sites in C++, C#, Java, Kotlin, Python and PHP
  delegate to it.
- **The copies had already diverged.** They enabled the same parser features in different orders, and only
  some of them stripped a declared `DOCTYPE` before parsing — so the same report parsed in one adapter and
  failed in another. A defence against external-entity expansion and billion-laughs that has to be applied in
  nine places is a defence with nine chances to be missed; a future hardening fix now has one destination.
- **The hardening is belt and braces, deliberately.** `disallow-doctype-decl` makes any DOCTYPE a parse error;
  the DOCTYPE is also removed from the text first, so a report that carries `<!DOCTYPE testsuite>` out of habit
  still parses instead of being reported as a broken build. External general and parameter entities are
  disabled, XInclude is off, and external DTD and schema access is emptied — so nothing outside the file is
  fetched even if a future parser ignores the DOCTYPE flag.
- A byte-order mark is tolerated, because reports written on Windows routinely carry one.

## Verified for this release

- Full reactor test suite: **1719 tests, 0 failures** across all 22 modules (up from 1713).
- New tests pin the security contract rather than the implementation: a plain report parses; a byte-order
  mark does not stop it; a declared DOCTYPE is stripped rather than failing; an external entity pointing at a
  local file cannot put that file's contents into the document; the ten-level billion-laughs document does not
  expand; and a document that is not well formed is a parse error rather than a silent empty result.
- Every adapter's own report-parsing tests pass unchanged, which is the evidence that unifying the loader did
  not change what real reports parse to.

## Compatibility

- Security and maintainability release: no report format, verdict, exit code, CLI or configuration change.
