**CodeWitness 1.0.19** clarifies the TypeScript parameter properties limitation and documents the workaround.

## What changed

- **Documentation: TypeScript parameter properties** — Explicitly documents that Node's type stripper does not support TypeScript parameter properties (`constructor(private x: T)`), which fail with "TypeScript parameter property is not supported in strip-only mode". Projects using these features should add a pinned TypeScript compiler and `tsconfig.json`, which makes CodeWitness use `tsc --noEmit` for full type checking instead of the fallback syntax checker.

- **New workaround documentation** — Added `docs/workarounds/` directory with detailed guidance on the TypeScript parameter properties limitation, including multiple workaround options and their tradeoffs.

## What this does not fix

- The underlying Node.js experimental `stripTypeScriptTypes` limitation remains; the workaround (adding TypeScript compiler) is the actual fix for affected projects.

## Verified for this release

- 1,759 tests across 22 modules: **0 failures, 0 errors**
- Documentation updated: `docs/status.md`, `docs/workarounds/README.md`, `docs/workarounds/typescript-parameter-properties.md`
- No code changes: this release is documentation-only

## Compatibility

- No breaking changes
- Existing TypeScript projects continue to work as before
- Projects using parameter properties without a TypeScript compiler will continue to get clear error messages directing them to the workaround

## Notes

This release addresses a user question: "why does my TypeScript code fail?" The answer was already correct (the error message clearly states the problem), but now documented how to fix it explicitly.
