**CodeWitness 1.0.3** starts removing the adapter duplication from the inside: one declaration now feeds an adapter and
its bundle, and the capability list can no longer disagree with it.

## What changed

- **`AdapterProviders`** is the set of tools one language uses, declared once. Every adapter had the same three
  problems written out by hand: its bundle registered a list of providers, its `build`/`runTests`/`analyze` were
  one-line delegations to providers that were *also* registered, and `capabilities()` restated that list as a second,
  independently maintained set. Nothing connected them.
- **`AbstractLanguageAdapter`** implements those three methods over the declared set and derives `capabilities()` from
  it. A capability cannot disagree with a registration because it is computed from one.
- **`capabilities()` now answers a narrower question, correctly.** It reports what the adapter can actually serve:
  `includeAnalysis=false` withdraws `STATIC_ANALYSIS` and `SECURITY_SCAN` instead of leaving the adapter claiming a
  phase with nothing to run, and `GENERATED_TESTS` requires both a generator *and* an executor, because a scenario
  that cannot be executed is not a test.
- **Rust is converted** as the pattern's proof: `RustLanguageAdapter.rustProviders()` is the single declaration,
  `RustAdapterBundle.register` registers it, and the adapter's three delegating methods and hand-written capability
  list are gone. Fourteen adapters remain, and the 0.1.15 capability guard will report any of them whose derived set
  disagrees with what it registered.

## Verified for this release

- Full reactor test suite: **1739 tests, 0 failures** across all 22 modules (up from 1734).
- New tests pin the derivation: capabilities are exactly the phases the declared providers serve; a capability nobody
  declared is not advertised; generated tests need both halves; `includeAnalysis=false` withdraws the analysis
  capabilities and does not register the analyzers; calling a phase with no provider fails with a message naming the
  capability it needs; and the returned set is immutable.
- The Rust adapter's own tests — detection, build, tests, coverage, mutation, dependencies and scenario generation —
  pass unchanged, which is the evidence that the conversion preserved its behaviour rather than only its shape.

## Compatibility

- Additive and internal: no report format, verdict, exit code, CLI or configuration change. The one behavioural
  difference is the narrower capability set when a bundle is registered without analysis, which is what that flag
  always meant.
